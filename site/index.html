Which NSE stocks are sliding into illiquidity, and which signal actually says so

A reproducible pipeline on 68 Nairobi Securities Exchange equities, 2013 to October 2024, real daily price and volume data. Built to answer one question an investment desk actually asks: can a position in this name be exited without moving the market in the next week — and does a model beat a simple rule at predicting when that stops being true?

View the pipeline on GitHub
  • 68NSE-listed equities, 2013-2024
  • 25.1%of all stock-sessions were untraded
  • 11.3%of currently-liquid names turn illiquid within 5 sessions
  • 0.584model PR-AUC on that harder subset, vs 0.517 for a fixed rule
Results

The model beats the rule every year — modestly

Not one lucky split: the same model, refit on an expanding window, outperforms the fixed rule's ranking in every one of 9 overlapping test years (a stability check across years of the same pair of scorers, not nine independent replications).

Why "full population" overstates it. Most of the illiquidity in 40.8% of all rows is a stock that was already illiquid staying that way — persistence alone gets 72.127% PR-AUC for free. The question worth answering is the harder one: among the 110,765 stock-sessions that were NOT already illiquid, which ones turn within 5 sessions? There, persistence cannot even be defined usefully (it predicts nothing, since by definition these rows are not currently illiquid), the fixed rule gets 0.517, and the model gets 0.584 — a real, modest improvement, not a free one.

Where the model actually adds value. At the rule's own flag count (25 flags), the model's top-ranked rows are the exact same as the rule's — precision 84%, recall 1.1%, identical. The model's higher PR-AUC comes from ranking better below that cutoff, not from beating the rule at the operating point a desk would actually use today. A lower, better-chosen cutoff is the natural next question, not answered here.

Data engineering

Why a dense per-stock session grid exists

A real frontier-market data-quality finding, caught before it reached a model.

187,792 stock-session rows in the dense grid. 1,749 of those are sessions the source simply has no row for at all — not a zero, an absence. Confirming this before writing any rolling window mattered: a window function over the raw sparse table would have silently stretched "the next 5 sessions" across however many calendar gaps happen to fall in the way.

A further 45,392 rows are present but explicitly marked not traded (the source writes "-", never a literal 0). Both cases mean the same thing for this project: untraded.

How it is built

One folder per stage, runnable end to end

The same shape as this portfolio's other data pipelines: small scripts, plain loops, real checks.

1-2. Ingest and clean. Four public Mendeley Data archives (one author, one schema, CC BY 4.0), downloaded with no login. Real schema drift handled: column names and even the date format change between the 2013-2021 files and the 2022-2024 files.

3. Warehouse. DuckDB, loaded from cleaned parquet.

4. SQL models. A dense per-stock session grid first, then window-function features (ROWS BETWEEN, never a date range), then the forward and trailing labels, then the analysis mart. Plain numbered .sql files, no dbt.

5. Checks. 8 SQL checks that must return zero rows: no duplicate sessions, the grid never leaves a stock's own listed life, both labels are NULL in exactly the rows they should be, no negative volume, dates in range, every price code has a sector.

6-7. Baseline and model. A naive persistence guess and a fixed rule, then a logistic regression, compared like-for-like by matching flag counts, not by a fixed probability cutoff that a rare label would make meaningless.

8-10. Report, figures, site. Every number above traces to outputs/results.json.

Limits

Read before citing a number from this page

  • This is a frozen historical archive (last update November 2024), not a live feed. There is deliberately no scheduled refresh — a live version would need a paid or scraped real-time NSE feed, which this project does not have.
  • Indices (codes starting with ‘^’, e.g. the NSE All-Share Index) are excluded from the universe: an index has no comparable single-instrument trading volume.
  • Returns are computed from the raw close, which is echoed unchanged on an untraded day (the source repeats the last traded price rather than leaving it blank). That makes 20-day return volatility understate true volatility on the thinnest names — a day with no trade is not really a zero-return day, it is a missing one.
  • volume_zscore_60d is undefined (not computed) for a stock with zero trading volume for 60 straight sessions — a real state for several names in this market, not a bug.
  • The logistic regression's standardised coefficients describe association within this sample, not a causal claim about what drives illiquidity.
  • Sector is shown for grouping only; it is never a model input, because it is static and would mostly just memorise which names are already known to be thin.
  • The ‘days to exit’ column on the watchlist is an illustrative execution rule of thumb (20% daily participation), not a market-impact model.
